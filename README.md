## 1 неделя — Наталья Смолина

### Эксперимент 1. Проверка TEI и первоначальная настройка LLM

#### Цель

Запустить модели на ноутбуке и проверить, насколько хорошо TEI определяет смысловую близость текстов.

#### Что сделали

- Запустили TEI с моделью `bge-m3` в Docker.
- Проверили преобразование текстов в числовые векторы и сравнили их близость.
- Запустили Ollama с моделью `Qwen3:8B` в Docker и настроили первоначальное подключение через OpenAI-совместимый API.

#### Результаты

- TEI успешно преобразует каждый текст в вектор из **1024 чисел**.
- Скорость обработки одного текста — около **250 мс**.
- Близость текстов про возврат денег составила **0,806**, а текстов про возврат и доставку — **0,669**. Модель различает темы, но для точного отбора документов потребуется дополнительная проверка.
- При работе с Qwen3:8B возникли проблемы: модель слишком долго генерировала ответы, из-за чего запросы завершались по таймауту.

#### Вывод

TEI подходит для поиска похожих текстов. Ollama удалось запустить, но подключение к Qwen3:8B требовало доработки.

**Результаты TEI:** [01-tei-embed-results.md](docs/experiments/01-tei-embed-results.md)

## 2 неделя — Наталья Смолина

### Эксперимент 2. Настройка LLM, классификация обращений и генерация ответов

#### Цель

Устранить ошибки работы Qwen3:8B, реализовать классификацию обращений и генерацию ответов по документам базы знаний.

#### Что сделали

- Перешли с OpenAI-совместимого API на нативный API Ollama `/api/chat`.
- Отключили режим рассуждений (`thinking`), вызывавший длительную генерацию и таймауты.
- Настроили получение структурированного JSON и проверку его корректности.
- Реализовали классификацию обращений по теме, срочности, настроению и необходимости оператора.
- Провели эксперимент на 10 обращениях клиентов.
- Выделили общий LLM-клиент в `ollama.py`, сохранив поддержку Ollama и vLLM.
- Реализовали генерацию ответов по документам с указанием источников.
- Добавили эскалацию при недостатке информации и доработали промпт для предотвращения неподтверждённых ответов.
- Провели автоматические тесты и проверку генерации на реальной модели в Docker.

#### Результаты

- Устранены ошибки подключения и таймауты при классификации.
- **18/18 автоматических тестов** пройдены.
- **10/10 запросов** классификации выполнены без ошибок.
- Точность определения темы — **100%**, настроения — **100%**, срочности — **60%**, необходимости оператора — **70%**.
- Среднее время классификации: первоначально **35,6 с**, после рефакторинга — **39,8 с**.
- **3/3 сценария генерации** выполнены корректно после доработки промпта.
- Среднее время генерации — **58,6 с**.
- Модель корректно указывает источники и передаёт обращение оператору при недостатке информации.

#### Вывод

Устранены проблемы взаимодействия с Qwen3:8B. Реализованы классификация обращений и генерация ответов на основе документов через общий LLM-клиент. Компоненты готовы к дальнейшей интеграции в RAG-систему, однако требуют оптимизации скорости и дополнительной проверки качества.

**Результаты классификации:** [02-classify-results.md](docs/experiments/02-classify-results.md)

## 3 неделя — Наталья Смолина

### Эксперимент 3. Контракт API эмбеддингов TEI

#### Цель

Зафиксировать и проверить контракт между клиентом приложения и TEI, чтобы некорректный ответ сервиса не принимался за успешно полученные эмбеддинги.

#### Что сделали

- Уточнили контракт клиента `TeiEmbedder`: непустой список текстов отправляется на `POST /embed`; ожидается один вектор размерности 1024 на каждый текст.
- Добавили проверку корректности ответа TEI: некорректный JSON, неверная структура или размерность вектора, нечисловые и не конечные значения вызывают явную ошибку.
- Добавили unit-тесты на корректные и ошибочные ответы TEI с `httpx.MockTransport`.
- Создали smoke-проверку пакетного и одиночного запросов к реальному TEI.
- Проверили сервис TEI с моделью `BAAI/bge-m3` в Docker на MacBook Air.

#### Результаты

- **14/14 тестов** клиента TEI пройдены; весь набор тестов библиотеки `ai-clients` также пройден — **25/25**.
- Проверка реального сервиса прошла: `/health` вернул `200 OK`.
- На два текста получено два вектора размерности **1024**; значения возвращены как `float`.
- Одиночный запрос также успешно обработан.
- Время пакетного запроса для двух текстов — **1951 мс**, одиночного запроса — **472 мс** на проверенной машине.

#### Вывод

Контракт клиента TEI проверен автоматическими тестами и на работающем сервисе. Клиент явно сообщает об ошибках формата и значений в ответе, а реальный TEI возвращает ожидаемое количество векторов с нужной размерностью. Это подтверждает готовность клиентского контракта, но ещё не означает интеграцию TEI с индексацией базы знаний или поиском в Worker.
