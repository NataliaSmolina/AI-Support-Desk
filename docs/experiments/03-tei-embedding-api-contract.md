# Эксперимент 3. Контракт API эмбеддингов TEI (коммит 1)

## Цель

Зафиксировать и проверить контракт между приложением и TEI, чтобы последующая интеграция с индексацией и поиском не принимала некорректный ответ модели за успешный.

## Системы

- TEI с `BAAI/bge-m3`, запускаемый через `infra/tei/compose.yml`.
- Клиент `TeiEmbedder` из общей библиотеки `ai-clients`.
- Unit-тесты клиента с `httpx.MockTransport` — не требуют Docker или запущенной модели.
- Smoke-проверка на работающем TEI — подтверждает формат ответа реального сервиса.

## Контракт

| Условие | Ожидаемое поведение |
|---|---|
| Вход | Непустой список непустых текстов |
| Endpoint | `POST /embed` с JSON `{"inputs": [...]}` |
| Количество результатов | Один вектор на каждый текст, в исходном порядке |
| Размерность | 1024 значения на вектор для `BAAI/bge-m3` |
| Значения | Конечные числа, возвращаемые клиентом как `float` |
| Ошибки сервиса или ответа | Явная `EmbeddingServiceError`, не успешный результат |

Клиент передаёт текстовый список в исходном порядке и возвращает векторы в порядке ответа TEI. Unit-тест проверяет тело запроса и порядок возвращаемых векторов.

## Как запускали

Unit-тесты не требуют работающей модели:

```bash
uv run pytest libs/ai-clients/tests/test_tei.py
```

Проверка на реальном TEI требует запущенного Docker-сервиса:

```bash
docker compose up -d tei
uv run python evals/check_tei_contract.py
```

Smoke-скрипт проверяет пакетный и одиночный запросы, размерность и числовой тип векторов. Он записывает замер в [отдельный отчёт live-проверки](03-tei-embedding-api-contract-live-results.md), не перезаписывая результаты unit-тестов.

## Критерии завершения

- Unit-тесты проверяют корректный ответ, порядок, HTTP-ошибку, недоступность сервиса, неверное количество/размерность векторов и некорректную структуру/значения.
- Smoke-проверка реального TEI завершается с кодом 0 и сохраняет результаты.
- Ошибка формата ответа явно сообщается вызывающему коду как `EmbeddingServiceError`.

## Границы эксперимента

Эксперимент проверяет клиентский API-контракт и базовую доступность TEI, а не качество семантического поиска. Подключение эмбеддингов к индексации базы знаний и Worker относится к следующим этапам.
