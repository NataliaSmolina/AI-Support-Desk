## Worker

Доработал Worker, чтобы он не только находил новое обращение, но и получал текст первого сообщения клиента из таблицы `messages`.

Добавил перевод обращения в статус `processing`, фиксацию времени начала обработки в `locked_at` и увеличение счётчика попыток в `attempts`. Для безопасного получения обращений использовал `FOR UPDATE SKIP LOCKED`, чтобы несколько экземпляров Worker могли работать параллельно, не забирая один и тот же тикет.

Проверил работу Worker на тестовом обращении и убедился, что он забирает тикет из PostgreSQL и выводит его данные. Также проверил поведение при отсутствии новых обращений.

## 3 спринт 13.10 - 19.10
## PostgreSQL
добавил миграцию 003 для таблицы tickets. Новые поля нужны, чтобы worker мог повторять обработку после ошибок и находить зависшие обращения.

| Поле              | Тип данных      | Описание                                                                |
| ----------------- | --------------- | ----------------------------------------------------------------------- |
| `locked_by`       | `VARCHAR(100)`  | Какой worker сейчас обрабатывает обращение                              |
| `next_attempt_at` | `TIMESTAMPTZ`   | Когда обращение можно брать в обработку снова (пауза между повторами)   |
| `last_error`      | `TEXT`          | Текст последней ошибки обработки                                        |
| `sentiment`       | `VARCHAR(20)`   | Настроение клиента, которое определила модель                           |
| `wants_human`     | `BOOLEAN`       | Просил ли клиент позвать оператора                                      |

Также добавил два индекса: для быстрого поиска новых обращений и для поиска зависших.

## Worker
перенёс worker в `services/worker` и подключил классификацию обращений через `LlmClassifier`. Результат (категория, приоритет, настроение, просьба позвать человека) сохраняется в `tickets`, обращение получает статус `classified`.

Добавил обработку ошибок и повторные попытки. Если обработка падает, обращение возвращается в очередь со статусом `new` и ждёт перед повтором 5, 10, 20 секунд. Текст ошибки сохраняется в `last_error`. После 3 попыток обращение получает статус `failed` и передаётся оператору. Если текст обращения пустой, повторять нет смысла, и оно сразу уходит оператору.

Добавил восстановление зависших обращений. Раз в 30 секунд worker проверяет, нет ли обращений в статусе `processing`, у которых `locked_at` старше 5 минут. Такие обращения возвращаются в очередь, а если попытки уже закончились, то передаются оператору.

Чтобы не забрать обращение у работающего worker, во время обработки он раз в 60 секунд обновляет `locked_at`. Кроме того, все изменения обращения проверяют поле `locked_by`: если обращение у worker уже забрали, его запоздалый результат игнорируется.
