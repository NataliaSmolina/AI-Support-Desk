# Telegram-бот поддержки

Принимает вопросы клиентов в Telegram. Позже будет сохранять их в базу для worker'а и показывать операторам черновики ответов.

## Как запустить

1. Получить токен у [@BotFather] и вписать его в `.env` строкой `BOT_TOKEN=...`
2. Запустить из корня проекта

```bash
uv run python -m support_bot.main
```

Остановить – `Ctrl+C`. Запустить тесты – `uv run pytest`.

### Группа операторов (необязательно)

Без нее бот работает, но карточки операторам не отправляет.

1. Создать группу с темами, добавить в нее бота.
2. В нужной теме отправить `/chat_id` – бот ответит двумя строками.
3. Вписать их в `.env` и перезапустить бота

```
OPERATOR_CHAT_ID=-100...
OPERATOR_THREAD_ID=...
```

### Что нового изучено

**aiogram 3** – библиотека для Telegram-ботов, бот собирается из подключения, распределителя событий и хендлеров
- `Bot` – подключение к Telegram
- `Dispatcher` – распределяет события
- `Router` – набор хендлеров, хендлер – функция «что делать, когда пришло X»

**Фильтры** – условия, по которым aiogram выбирает, какой хендлер вызвать для сообщения
- `CommandStart()` – срабатывает на команду `/start`
- `Command("help")` – срабатывает на команду с указанным именем, здесь `/help`
- «Магический» фильтр `F` – проверяет поля сообщения: `F.text` – в сообщении есть текст, `~F.text` – нет текста
- Хендлеры проверяются сверху вниз до первого подходящего, поэтому порядок важен – хендлер для не-текста стоит последним

**async / await** – асинхронный код, пока одна операция ждет ответа по сети, программа занимается другими
- `async with` сам закрывает соединение при остановке

**Настройки** – значения, которые меняются от запуска к запуску, хранятся вне кода и читаются при старте
- pydantic-settings – библиотека, которая читает `.env` и превращает строки в нужные типы
- `SecretStr` – тип для секретов, при печати показывает `**********` вместо токена
- `Field(min_length=1)` – правило для поля, пустой токен не пройдет проверку и бот не запустится

**Логи** – записи о работе программы, по ним видно, что происходило и где возникла ошибка
- У каждой библиотеки свой журнал, уровень можно менять для каждого отдельно

**Тесты** – код, который проверяет код, без Telegram и интернета
- pytest – запускает тесты, то есть все функции `test_...` из папок `tests`
- `AsyncMock` – заглушка вместо настоящего объекта, запоминает, что с ней делали. «Async» – потому что умеет работать с `await`
- `SimpleNamespace` – простой объект с нужными полями, например поддельное сообщение с полем `text`
- `caplog` – встроенный помощник pytest, собирает логи во время теста, чтобы их можно было проверить
- `monkeypatch` – временно задает переменные окружения на время теста, после теста все возвращается как было

## #2 Commit – 09.10.26

`9ac6f57` бот: обработка ответов, карточка операторам, /chat_id

### Что сделано

- Бот отвечает «Принято, ищу решение» на любой текстовый вопрос клиента.
- Хендлеры клиента работают только в личке, хендлеры операторов – только в группе
- На каждый вопрос в группу операторов уходит карточка с вопросом, черновиком ответа и кнопками «Отправить» / «Исправить»
- Черновик пока тестовый, кнопки пока не обрабатываются
- Команда `/chat_id` в группе подсказывает номера группы и темы для `.env`
- Ветка слита с `main` (LLM, PostgreSQL, worker), PR #5 с ботом принят в `main`

### Почему так

- **Фильтр «только личка».** Бот состоит в группе операторов, без фильтра он отвечал бы «Принято» на каждое их сообщение
- **`CallbackData`, а не строка вручную.** Сам упаковывает данные в кнопку и распаковывает обратно с проверкой типов
- **Настройки через `Dispatcher(settings=...)`.** Хендлер получает настройки аргументом, в тестах их легко заменить заглушкой
- **Карточку пока шлет сам `question`.** Временно, пока нет worker'а и таблицы для текста вопроса

### Предложения агента и принятые решения

| Предложение агента | Принятое решение |
|---|---|
| Обычная группа для теста | Группа с темами, добавлен номер темы |
| Тесты по ситуации | Простые тесты сразу на каждый коммит |

### Что нового изучено

**Inline-кнопки** – кнопки прямо под сообщением бота
- `InlineKeyboardButton` – одна кнопка под сообщением, у нее есть подпись и скрытые данные
- `InlineKeyboardMarkup` – клавиатура из кнопок, задается списком рядов, `[[a, b]]` – один ряд из двух кнопок
- Callback – нажатие на кнопку, приходит боту отдельным событием вместе со скрытыми данными

**CallbackData** – способ описать данные, зашитые в кнопку, Telegram хранит их строкой до 64 байт
- `DraftAction` – наш класс с полями `action` (что сделать) и `chat_id` (кому ответить)
- `pack()` – превращает объект в строку для кнопки, например `draft:send:111`
- `unpack()` – превращает строку из нажатой кнопки обратно в объект

**Внедрение зависимостей** – хендлер не создает нужные объекты сам, а получает их аргументами от aiogram
- `bot` – aiogram подставляет всегда, через него можно писать в любой чат, а не только отвечать
- `Dispatcher(settings=...)` – все, что передано сюда, aiogram подставит в хендлеры с аргументом такого же имени

**Группы в Telegram** – операторы работают в общей группе с темами, бот пишет в нужную тему
- `group` и `supergroup` – два типа групп в Telegram, группа с темами всегда `supergroup`
- `message_thread_id` – номер темы в группе, `None` – общая тема
- `F.chat.type` – фильтр по типу чата (`private`, `group`, `supergroup`)
- `router.message.filter(...)` – фильтр сразу на все хендлеры роутера, а не на каждый по отдельности

**Python** – новые конструкции языка, которые пригодились в коде
- `int | None` – тип «число или ничего», современная замена `Optional[int]`
- Ранний выход – если дальше делать нечего, функция сразу завершается через `return`, без вложенных `if`
- `env_ignore_empty` – настройка pydantic-settings, пустая строка в `.env` считается «не задано»

**Git в команде** – работа с общим репозиторием, куда коммитят и коллеги
- `origin` и `upstream` – свой форк и общий репозиторий, у каждого свое имя в git
- `git merge upstream/main` – подтянуть изменения коллег в свою ветку
- Конфликт – обе стороны изменили одни и те же строки, git просит выбрать вариант. Решается в PyCharm, в окне из трех колонок (мое, итог, чужое)
- PR в `main` – запрос на слияние своей ветки с общей, коллеги смотрят изменения и принимают
- `--amend` – дополнить последний коммит вместо нового, можно только пока он не отправлен

**Тесты** – новый прием проверки
- `await_args.kwargs` – заглушка запоминает, с какими аргументами ее вызвали, и это можно проверить
