# Telegram-бот поддержки

Принимает вопросы клиентов в Telegram и сохраняет их в PostgreSQL для worker. Клиент получает номер обращения и может посмотреть последние 5 обращений через `/status`.

В группу операторов приходит карточка с номером тикета и тестовым черновиком. Кнопка «Отправить» получает чат клиента из базы по номеру тикета. После подтверждения Telegram бот сохраняет отправленный текст в истории обращения с автором `operator`. На карточке видно, удалось ли сохранить ответ. Настоящие черновики и смена статуса после отправки пока не подключены. Кнопка «Исправить» пока показывает заглушку.

## Как запустить

1. Получить токен у [@BotFather](https://t.me/BotFather) и вписать его в `.env` строкой `BOT_TOKEN=...`
2. Запустить из корня проекта

```bash
uv run python -m support_bot.main
```

Остановить – `Ctrl+C`. Запустить тесты – `uv run pytest`.

### База данных (необязательно)

В `.env` используется та же переменная `DATABASE_URL`, что у worker. Нужна база с примененными миграциями проекта, в том числе таблицами `tickets`, `messages` и `tg_updates`. Для общей базы также нужен доступ через Tailscale.

```dotenv
DATABASE_URL=postgresql://USER:PASSWORD@HOST:PORT/DB_NAME
```

Без `DATABASE_URL` бот принимает сообщения без сохранения и номера обращения. `/status` сообщает, что список недоступен, а карточки операторов приходят без кнопок. Если адрес задан, но база недоступна, бот не подтверждает сохранение вопроса и просит попробовать позже.

Тесты бота на настоящей базе запускаются отдельно

```bash
uv run pytest -m integration services/bot
```

Они используют откатываемые транзакции. Строки тестов не сохраняются, но счетчик номеров тикетов может увеличиваться даже после отката, поэтому пропуски номеров допустимы.

### Команды клиента

- `/start` – приветствие
- `/help` – как пользоваться ботом
- `/status` – последние 5 обращений с номером, датой, временем по Москве и статусом, без текста вопроса

### Группа операторов (необязательно)

Без нее бот работает, но карточки операторам не отправляет.

1. Создать группу с темами, добавить в нее бота.
2. В нужной теме отправить `/chat_id` – бот ответит двумя строками.
3. Вписать их в `.env` и перезапустить бота

```
OPERATOR_CHAT_ID=-100...
OPERATOR_THREAD_ID=...
OPERATOR_IDS=[123456789]
```

`OPERATOR_IDS` – Telegram ID операторов, которым разрешено нажимать рабочие кнопки карточки. Пустой список запрещает нажатия всем. Без базы новые карточки отправляются без кнопок. Кнопки старых карточек с прежним форматом данных показывают предупреждение об устаревшей карточке.

## #3 Commit – 17.10.26

`74e705d` бот: кнопка «Отправить» – черновик клиенту, пометка в карточке

### Что сделано

- Кнопка «Отправить» работает. Клиент получает черновик в личку, карточка в группе получает пометку, кто отправил, кнопки исчезают.
- Если клиент заблокировал бота, оператор видит всплывающее окно, карточка не меняется.
- Если карточка старше 48 часов, оператор видит предупреждение – такие сообщения Telegram менять не дает.
- Кнопка «Исправить» пока показывает «Скоро будет» вместо бесконечных «часиков».

### Почему так

- **Черновик берется из `FAKE_DRAFT`, а не из текста карточки.** Разбор текста карточки сломался бы при любом изменении ее формата. Заглушка честно временная и заменится на «взять черновик заявки из базы».
- **После отправки кнопки убираются.** Так второй оператор не отправит тот же ответ повторно. Защита неполная – два почти одновременных нажатия могут пройти оба. Полное решение – статус заявки в базе.
- **Ошибка «клиент заблокировал бота» обрабатывается отдельно.** Без этого бот падал бы с ошибкой в логе, а оператор не понял бы, что ответ не доставлен.

### Предложения агента и принятые решения

| Предложение агента | Принятое решение |
|---|---|
| Сделать обе кнопки сразу | Одна кнопка за коммит – «Отправить» сейчас, «Исправить» через FSM следующим этапом |
| Черновик из `FAKE_DRAFT` или вырезать из текста карточки | `FAKE_DRAFT`, временное решение не притворяется постоянным |
| Заглушка «Скоро будет» на «Исправить» | Принято, чтобы кнопка не выглядела сломанной |

### Что нового изучено

**Callback** – нажатие на inline-кнопку, приходит боту отдельным событием, а не сообщением
- `@router.callback_query(...)` – хендлер на нажатия кнопок, как `@router.message` для сообщений
- `DraftAction.filter(F.action == "send")` – фильтр «нажата кнопка карточки с действием send», распакованные данные приходят в аргумент `callback_data`
- `callback.answer()` – ответ Telegram, что нажатие обработано, без него у оператора крутятся «часики»
- `callback.answer(текст, show_alert=True)` – всплывающее окно с кнопкой «ОК» вместо короткой подсказки
- `callback.message` – сообщение, под которым нажали кнопку, то есть карточка
- `callback.from_user.full_name` – имя того, кто нажал

- **`init: true`** – служебный процесс передает сигналы и помогает завершать дочерние процессы
- **`restart: unless-stopped`** – Docker перезапускает контейнер, если он не был остановлен вручную

### Что нового изучено

**Образ и контейнер** – образ содержит подготовленное окружение, а контейнер запускает его как отдельный процесс

**Dockerfile** – `FROM` выбирает базовый образ, `WORKDIR` задает рабочую папку, `COPY` переносит файлы, `RUN` выполняет команду при сборке, а `CMD` задает запуск контейнера

**Compose** – `services` описывает сервисы, `build` задает сборку, `context` определяет доступные при сборке файлы, а `env_file` передает настройки контейнеру

**Сеть Docker** – `127.0.0.1` внутри контейнера относится к нему самому, а `host.docker.internal` на Docker Desktop позволяет обратиться к Mac

**PostgreSQL в Docker** – порт Mac `5433` направляется на порт базы `5432`, а volume хранит данные отдельно от контейнера
